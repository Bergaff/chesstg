## 1. Выкат

1. **Бэкап перед схемой.** `npx wrangler d1 export pawn-vs-all --remote --output=backup-$(date +%F).sql`
2. **Миграция раньше кода.** `npm run db:status` → `npm run db:remote` (или весь
   `docs/db-setup.sql` в консоли D1 на панели - он идемпотентный).
   Порядок именно такой: чтение профиля переживёт отсутствие колонок
   (`customSlotsOf` опирается и на старый `custom_paid`), а запись покупки - нет.
3. **Номер сборки.** Поднять `version.json` на 1 (будет 46). Админка показывает
   «сборка N · воркер M»: без сверки номеров непонятно, что сейчас в бою.
4. **Зелёная ветка.** `npm ci && npm run typecheck && npx vitest run && npm run build`.
   Интеграционные тесты стучатся в живой воркер и пропускаются, если его нет, -
   перед релизом имеет смысл прогнать их с запущенным `npm run dev:worker`.
5. **Деплой.** Пуш в `main`, если сборка идёт из панели (Build command
   `npm run build`, Deploy command `npx wrangler deploy`), либо `npm run deploy`
   руками.
6. **Проверка.** `/api/health` → `build: 46`, `schemaVersion: 7`, `warnings: []`;
   `/api/session` гостя → в профиле `customSlots`, `customMaxSlots: 3`,
   `customSkins`.
7. **Бот.** @BotFather: `/newapp` (не `/newgame` - играм нужна `sendGame` и
   `setGameScore`, их у нас нет), название «Край доски», описание, иконка
   `public/icon-512.png`, URL приложения; затем `/setmenubutton` → текст `Играть`,
   `/setdescription`, `/setabouttext`, `/setuserpic`.
8. **Вебхук через админку.** `/admin` → вкладка «Бот» → секрет вебхука (тот же, что в
   секрете `WEBHOOK_SECRET`), адрес приложения, галки «Команды» и «Кнопка меню» →
   «Подключить бота». Проверка: `getWebhookInfo` - пустой `last_error_message` и
   `pending_update_count: 0`.
9. **Прогон на устройстве.** Первый уровень, смерть (списание жизни), награда
   уровня, покупка набора за звёзды и её отмена, `Привязать Telegram` из браузера,
   перезаход с сохранением партии. Полный чек-лист - §7 `deploy.md`.

Откат: `npx wrangler deployments list` → `npx wrangler rollback <id>`. У D1
автоматического `down` нет; миграция 0007 аддитивная (колонки + backfill), так что
откат приложения не требует отката схемы.

## 2. Реклама Adsgram

1. Кабинет Adsgram → приложение типа **Telegram Mini App**, ссылка
   `t.me/pawn_vs_all_bot`, иконка 512. Кабинет проверяет, что бот и адрес живые,
   поэтому шаг идёт после выката.
2. Внутри приложения - блок формата **Reward** (rewarded video). У нас один
   `blockId` на все точки начисления: клиентский `showAdsgram()` кэширует `init()`
   на страницу, поэтому второй блок в тот же контроллер не пройдёт - один ID на
   всё приложение.
3. Блок уходит на модерацию: в будни 4-6 часов, в выходные 6-10. Требования -
   приложение открывается и работает в момент проверки, команды бота отвечают и на
   мобильном, и на десктопе.
4. `ADSGRAM_BLOCK_ID` вписать **в `wrangler.jsonc` (`vars`)**, а не в панель:
   `wrangler deploy` публикует набор обычных переменных из файла и стирает то, что
   добавили руками в панели. Секреты так не затираются, обычные переменные - да.
5. `npm run build && npx wrangler deploy` (`ADSGRAM_SRC` оставляем
   `https://sad.adsgram.ai/js/sad.min.js`: SDK грузится на клиенте, ключей не нужно).
6. Проверка без игры: в `warnings` нет `adsgram_block_missing`, а
   `POST /api/ads/reward` с телом `{"kind":"probe"}` отвечает `400 bad_ad_reward`
   (было `503 ads_not_configured` - блок ещё не принят).
7. Проверка руками в Telegram: +30 монет из меню, +1 жизнь после поражения, щит
   перед уровнем. В обычном браузере SDK не играет - это ограничение окружения;
   в продакшене при недоступной рекламе игрок видит тост, и это правильно.
8. Кулдауны на сервере: жизнь 45 с, монеты 60 с, щит 20 с; при купленном
   «без рекламы навсегда» (150★) награды отвечают `403 ad_free`, а кнопки скрываются.
9. Выплаты кабинета: USDT в сети TON, минимум $100 в любой момент либо один вывод
   от 10 USDT в числа 1-5; KYC не требуется, заявки обрабатываются за сутки в будни.
   Цифры по курсу сети и правилам кабинета меняются - сверяйтесь в кабинете.
10. Честный масштаб. eCPM в rewarded - порядка 0.5-1 USDT за тысячу показов и
    сильно зависит от страны, поэтому реклама монетизирует тех, кто не платит, а
    не заменяет Stars: рассчитывать на неё как на основную выручку нельзя.
11. Накрутка. Сейчас награда выдаётся по клиентскому `done` от SDK плюс серверные
    кулдауны; суточного потолка нет (цифра «5 показов в день» в README - допущение
    модели `AD_COINS_DAILY_LIMIT`, она не ограничивает ничего живого). Перед
    закупкой трафика нужно: (а) суточный лимит на выдачу в `/api/ads/reward`,
    (б) серверная проверка Adsgram - `Reward URL`, куда Adsgram шлёт GET с
    Telegram id игрока (по их рекомендации - после 50k DAU, но дешевле сделать
    сразу). Иначе «телефон на столе» превращается в печать монет.

## 3. Деньги: Telegram Stars

- Звёзды падают на баланс бота, а не на личный; каждая звезда становится доступна
  для вывода через 21 день после платежа (окно, в которое покупатель ещё может
  оспорить покупку в сторе).
- Вывод - через Fragment в TON (ныне GRAM) на свой кошелёк: минимум 1 000 звёзд,
  курс разработчика $0.013 за звезду, дальше продажа монеты на бирже.
- Альтернатива выводу - тот же баланс потратить на Telegram Ads: зачёт $0.02 за
  звезду, то есть в 1.5 раза выгоднее, чем выводить и покупать рекламу картой.
  Если вы всё равно собираетесь закупаться - выводите меньше.
- Обязанности продающего бота по правилам Telegram: отвечать на `/paysupport`
  (у нас команды нет), условия по понятному пути (`/terms` или ссылка; в игре
  условия и политика есть модалкой, публичного URL нет), канал поддержки
  (в `src/legal/content.ts` почта). Возврат - `refundStarPayment`; счёт и статус
  видно в админке, вкладка «Платежи».
- `config.paymentsEnabled` в `/api/health` = есть ли `BOT_TOKEN`. Без него магазин
  честно говорит «оплата звёздами ещё не подключена в этой сборке», и это не баг.
