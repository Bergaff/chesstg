# ♟ Пешка против всех

Telegram Mini App: одна пешка против целой шахматной доски. Поднимайся снизу вверх, обходи фигуры и не дай себя поймать. Тёмный минималистичный интерфейс, кампания, бесконечный режим, жизни, монеты и бонусы.

**Стек:** Cloudflare Workers + Hono + D1 · React 19 + Vite + TypeScript · Telegram WebApp API · Telegram Stars · Adsgram.

---

## Что внутри

- **Кампания** с сохранением прогресса. Размер поля и набор фигур растут вместе с уровнем.
- **Бесконечный режим** открывается после 10 уровня: поле удлиняется каждые 5 клеток, сложность — каждые 5 ходов.
- **5 жизней** ❤️, минус одна за поражение, восстановление по одной каждые 30 минут.
- **Монеты** 🪙 за победы и рекорды. Тратятся на подсказку, заморозку и отмену хода.
- **Бонусы:** подсказка 💡 20, заморозка ❄️ 30, отмена хода ↩️ 15.
- **Telegram Stars:** +5 жизней за 25 ⭐, навсегда без рекламы за 150 ⭐, набор из трёх скинов за 50 ⭐.
- **Rewarded-видео Adsgram:** +1 жизнь после поражения, щит на 3 хода перед уровнем, +30 монет из меню.
- **Рекорды:** глобальная таблица и друзья по реферальной ссылке.
- **Гостевой режим** для запуска в браузере без Telegram (отключается одной переменной).

### Правила

| Уровни | Поле | Фигуры |
| --- | --- | --- |
| 1–5 | 3×3 | пешка (с 1), ладья (с 3) |
| 6–15 | 4×4 | + слон (с 5), конь (с 8) |
| 16–30 | 5×5 | + ферзь (с 15) |
| 31+ | 6×6 | весь набор |

Пешка стартует в случайной клетке нижнего ряда и ходит только на одну клетку вперёд, влево-вперёд или вправо-вперёд. Бить нельзя. Если все три клетки закрыты или за краем — ход пропускается, но враги всё равно двигаются. Победа — любая клетка верхнего ряда. Поражение — фигура встала на клетку пешки (вражеская пешка бьёт и по диагонали вниз).

Фигуры ходят по классическим правилам, не бьют друг друга и жадно сокращают дистанцию до игрока. Ходят после игрока, все сразу, по одному разу.

## Архитектура

```
┌───────────────────────────────┐
│ Telegram / браузер            │
│ React + Vite (SPA)            │
│  · движок в src/engine        │
│  · локальный предпросмотр хода│
└──────────────┬────────────────┘
               │ /api/*  (initData или X-Guest-Id)
┌──────────────▼────────────────┐
│ Cloudflare Worker (Hono)      │
│  · проверка подписи initData  │
│  · серверный реплей партии    │
│  · экономика и идемпотентность│
└───────┬──────────────┬────────┘
        │              │
   ┌────▼────┐    ┌────▼─────────────┐
   │ D1 (SQL)│    │ Telegram Bot API │
   └─────────┘    │ · webhook        │
                  │ · Stars invoices  │
                  └───────────────────┘
```

Сервер не доверяет клиенту: в D1 хранится только `seed`, начальное состояние и список действий. Любой запрос воспроизводит партию единым TypeScript-движком (`src/engine`), поэтому накрутить монеты или уровень подменой состояния нельзя. Сохранения оптимистичные (`WHERE actions = ?`), финиш идемпотентен по `finish_id`.

## Локальный запуск

Требуется Node.js 20+ и npm.

```bash
npm install

# 1) локальная база D1
npm run db:local

# 2) API на http://localhost:8787 (нужен dist/index.html — см. ниже)
mkdir -p dist && echo '<!doctype html><title>API</title>' > dist/index.html
npm run dev:worker

# 3) в отдельном терминале — UI на http://localhost:5173
npm run dev
```

`vite.config.ts` проксирует `/api` на `127.0.0.1:8787`. Открой `http://localhost:5173` — приложение стартует в гостевом режиме (`ALLOW_GUESTS=true`), реклама заменяется пятисекундной демо-заглушкой (`DEV_MODE=true`).

Проверки:

```bash
npm run typecheck   # клиент + worker
npm test            # движок и UI-smoke
npm run build       # production-сборка в dist/
```

Интеграционные тесты ходят в живой Worker. Запусти `npm run dev:worker` в отдельном терминале и выполни `npm run test:api` (или `npm test`). Если API на `8787` недоступен, сьют пропускается и обычный `npm test` остаётся зелёным на чистой машине.

Сборка `npm run preview` поднимает собранный SPA и API на одном порту `8787` — удобно проверить прод-поведение Worker.

### Переменные окружения

Публичные переменные лежат в `wrangler.jsonc` (`vars`), секреты — только через `wrangler secret put` или `.dev.vars`.

| Переменная | Где | Назначение |
| --- | --- | --- |
| `WEBAPP_URL` | vars | Публичный HTTPS-адрес приложения (для кнопок бота) |
| `BOT_USERNAME` | vars | Username бота без `@`; нужен для ссылок-вызовов |
| `ALLOW_GUESTS` | vars | `true` — разрешает браузерный гостевой режим |
| `DEV_MODE` | vars | `true` — демо-реклама, dev-бейдж, разрешает webhook без секрета |
| `ADSGRAM_SRC` | vars | URL SDK Adsgram |
| `ADSGRAM_BLOCK_ID` | vars | ID рекламного блока Rewarded Video |
| `BOT_TOKEN` | secret | Токен бота из BotFather |
| `WEBHOOK_SECRET` | secret | Секрет заголовка `X-Telegram-Bot-Api-Secret-Token` |

`.dev.vars.example` — шаблон для локального запуска с реальным ботом. Файл `.dev.vars` в git не попадает.

## Деплой на Cloudflare

Подробная пошаговая инструкция — в [`docs/deploy.md`](docs/deploy.md). Кратко:

```bash
npx wrangler login
npx wrangler d1 create pawn-vs-all
# → вставь database_id в wrangler.jsonc

npm run db:remote
npx wrangler secret put BOT_TOKEN
npx wrangler secret put WEBHOOK_SECRET
npm run deploy

# webhook
curl "https://api.telegram.org/bot$BOT_TOKEN/setWebhook" \
  -d "url=https://<worker>.workers.dev/api/telegram/webhook" \
  -d "secret_token=$WEBHOOK_SECRET" \
  -d 'allowed_updates=["message","pre_checkout_query"]'
```

После деплоя:

1. В `wrangler.jsonc` замени `WEBAPP_URL` на `https://<worker>.workers.dev` (или свой домен), `BOT_USERNAME` — на username бота. Для продакшена поставь `DEV_MODE: "false"`; `ALLOW_GUESTS` оставь `true`, если хочешь открывать игру по обычной ссылке.
2. В BotFather: `/newapp` → выбери бота → URL приложения. Там же `/setmenubutton` с тем же URL.
3. Проверь `/api/health`, открой Mini App из бота, пройди уровень.
4. Для Stars ничего дополнительно подключать не нужно: бот выставляет счёт в `XTR` через `createInvoiceLink`, а оплату подтверждает `pre_checkout_query`.
5. Adsgram: создай Rewarded-блок в кабинете, вставь `ADSGRAM_BLOCK_ID`, задеплой заново.
6. Иконка 512×512 для BotFather и каталогов лежит в `public/icon-512.png`.

> `database_id` в репозитории — заглушка. Без реального ID `wrangler dev` работает с локальной D1, а `deploy`/`db:remote` — нет.

### Безопасность

- Подпись `initData` проверяется по HMAC-SHA256 (`WebAppData` + токен бота), `auth_date` живёт 48 часов.
- Гостевые запросы принимаются только при `ALLOW_GUESTS=true` и с 128-битным случайным ID.
- Все действия проверяются движком; сохранить «чужие» очки нельзя.
- Секреты не попадают в клиент: `/api/config` отдаёт только публичные поля.
- Для webhook рекомендуется `WEBHOOK_SECRET`; без него в продакшене эндпоинт отвечает 403.
- Возвраты Stars обрабатываются вебхуком `refunded_payment` и откатывают покупку.

## API

Все `/api/*`, кроме `health`/`config`, требуют `Authorization: tma <initData>` либо `X-Guest-Id: <32 hex>`.

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/health` | Проверка Worker и D1 |
| `GET /api/config` | Публичная конфигурация |
| `POST /api/session` | Профиль, активные забеги, реферал/вызов (`startParam`) |
| `GET /api/session` | Обновление профиля и жизней |
| `POST /api/run/start` | Начать или продолжить забег (`mode`) |
| `GET /api/run/:id` | Состояние забега |
| `POST /api/run/:id/save` | Оптимистичное сохранение действий |
| `POST /api/run/:id/finish` | Завершить забег, начислить награду |
| `POST /api/bonus/use` | Списать бонус из инвентаря или за монеты |
| `POST /api/shop/bonus` | Купить бонус в магазине |
| `POST /api/profile/skin` | Выбрать скин |
| `POST /api/ads/reward` | Награда за rewarded: жизнь / монеты / щит |
| `POST /api/shop/invoice` | Счёт Telegram Stars |
| `GET /api/pay/status` | Статус платежа |
| `GET /api/leaderboard` | Рекорды (`metric`, `scope`) |
| `POST /api/telegram/webhook` | Вебхук Telegram (секрет в заголовке) |

## Тесты и качество

- `src/engine/engine.test.ts` — правила, генерация, решатель, баланс, бесконечный режим.
- `src/engine/api.integration.test.ts` — полный цикл кампании по HTTP на живом Worker и локальной D1: старт, ходы, победа, бонусы, повышение уровня. Требует `npm run dev:worker`.
- `tests/ui.smoke.test.tsx` — jsdom-прогон интерфейса: меню, правила, магазин, рекорды, старт забега, ход, экраны победы и поражения, покупка бонуса.

Тесты движка проверяют в том числе:
- решатель действительно находит путь на сгенерированных уровнях;
- уровни до 90 проходимы (генератор с fallback);
- стоимости, награды и лимиты совпадают с таблицей выше;
- подсказка проецирует ровно два хода.

## Продуктовые решения и ограничения

- **Один движок на клиенте и сервере.** Клиент показывает ход мгновенно, сервер позже пересчитывает партию; рассинхрон лечится `actions_conflict` и финальным `finish`.
- **Undo** откатывает ход игрока вместе с ответом врагов (восстанавливается предыдущее состояние).
- **Freeze / shield** — это действия `buff` в логе, поэтому они переживают перезапуск и не дают читерить.
- **Подсказка** считается на клиенте DFS-решателем, сервер только списывает инвентарь. Это осознанный компромисс: подсказка не влияет на исход, а сервер остаётся простым.
- **Друзья** в рекордах — это приглашённые по реферальной ссылке: Telegram не отдаёт список контактов без явного разрешения.
- **Гостевой прогресс** привязан к браузеру и не переносится в Telegram-аккаунт.
- **Реклама** полностью скрыта после покупки «без рекламы»; сервер дополнительно отклоняет награды за неё с кодом `ad_free`.
- Для полноценной работы Adsgram SDK нужен реальный Telegram-клиент; в браузере включается демо-заглушка.
